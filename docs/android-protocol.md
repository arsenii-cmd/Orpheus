# Протокол телефон ↔ сервер Орфея

**Русский** · [English](android-protocol.en.md)

Приложение на телефоне — только транспорт. Оно само распознаёт лишь слово «Орфей»,
а звук фразы передаёт серверу. Сервер распознаёт речь (GigaAM), думает (Ollama) и
отвечает голосом (Piper). Здесь описано всё, что серверу нужно для приложения.
Эталонная реализация для проверки — `android/tools/mock_server.py`.

## Соединение

- Одно WebSocket-соединение: `ws://` или `wss://<сервер>/ws`. Путь задаётся в
  приложении целиком, так что может быть любым.
- Токен приходит в заголовке `Authorization: Bearer <токен>`. Если он неверный,
  сервер отправляет `error` и закрывает соединение.
- Соединение держится всё время, пока Орфей включён: ping каждые 20 с. После
  обрыва приложение переподключается сама, с паузами от 1 до 30 с.
- **Текстовые кадры** — JSON-сообщения, у каждого есть поле `type`.
- **Бинарные кадры** — звук: PCM, 16 бит, little-endian, моно.

## Телефон → сервер

| Сообщение | Когда |
| --- | --- |
| `{"type":"hello","device":"Pixel 8","version":1,"personal_key":"…"}` | Сразу после подключения. `personal_key` — ключ «Личного» (base64, 32 байта), если он задан в приложении: им сервер открывает зашифрованную личную память |
| `{"type":"mode","personal":true}` / `false` | Кнопка «Личное» в приложении: войти в раздел или выйти из него |
| `{"type":"start","sample_rate":16000,"follow_up":false,"wake_word":"орфей"}` | Началась фраза. Дальше идут бинарные кадры 16 кГц |
| … `"voice":"male"` или `"voice":"female"` в `start` | Необязательно: каким голосом ответить (мужской — Piper ruslan, женский — Piper irina). Без поля — голос сервера по умолчанию (`ORPHEUS_SERVER_VOICE`, мужской) |
| … `"enroll":true` в `start` | Фраза — не вопрос, а запись голоса владельца: сервер запоминает голос и вместо ответа шлёт `enroll`, затем `audio_end` |
| … `"headset":true` / `"headset":false` в `start` | Необязательно: фраза услышана микрофоном наушников / самого телефона. Отпечаток голоса подстраивается только по фразам из наушников (в них он записан); без поля — как раньше |
| … `"id":7` в `start` | Необязательно: номер фразы. Сервер повторяет его в `transcript`, `reply`, `audio`, `audio_end`, `error` и `enroll` этой фразы; телефон отбрасывает сообщения с чужим номером (ответ, прерванный кнопкой, может ещё идти, когда ушла следующая фраза). Без поля — как раньше |
| … `"strict":true` в `start` | Необязательно: отвечать на эту фразу только голосу владельца (приложение просит так в наушниках, тумблер «Строгий режим в наушниках»). Чужой голос — `audio_end` с `"reason":"not_owner"`, как при `ORPHEUS_SPEAKER=strict`. При `ORPHEUS_SPEAKER=off` не действует |
| `{"type":"enroll_reset"}` | Забыть записанный голос владельца. Сервер ответит `enroll` с `count: 0` |
| бинарные кадры | Звук фразы, по мере записи. Первый кадр может быть длиннее: это то, что было сказано сразу после слова активации |
| `{"type":"stop"}` | Телефон считает фразу законченной: 1 с тишины, 15 с максимум или сигнал `end_of_speech` от сервера |
| `{"type":"cancel"}` | Фраза отменена (после «Орфей» так ничего и не сказали, или Орфея выключили). Не отвечать |

`follow_up: true` означает, что фраза пришла в окне продолжения, без слова «Орфей».
Она может оказаться посторонним разговором: сервер вправе ответить пустым `audio_end`.

Звук начинается с конца слова «Орфей», но граница бывает неточной: в начале фразы
иногда проскакивает «фей» или «Орфей». Перед тем как отдавать распознанный текст
модели, такое начало стоит отрезать.

## Сервер → телефон

| Сообщение | Смысл |
| --- | --- |
| `{"type":"end_of_speech"}` | Необязательно: VAD на сервере решил, что фраза кончилась. Телефон ответит `stop` и перестанет слать звук. Серверный VAD точнее телефонного |
| `{"type":"transcript","text":"какая погода"}` | Что распознано. Телефон показывает это в истории |
| `{"type":"reply","text":"…"}` | Текст ответа. Может прийти несколькими кусками, они дописываются друг к другу |
| `{"type":"audio","sample_rate":22050}` | Сейчас пойдёт голос ответа: бинарные кадры с этой частотой |
| бинарные кадры | Голос ответа, можно слать по мере синтеза (по предложениям) |
| `{"type":"audio_end","expect_reply":false}` | Ответ закончен. `"reason":"not_owner"` — голос не владельца (режим `strict`): ответа не было и не будет, телефон просто ждёт «Орфей» дальше. `expect_reply: true` — Орфей задал вопрос, и телефон будет слушать ответ без слова активации, даже если продолжение выключено в настройках |
| `{"type":"error","message":"…"}` | Ошибка: телефон пикнет и покажет текст |
| `{"type":"mode","personal":true}` / `false` | Текущий раздел: сразу после `hello` и при каждой смене — кнопкой, голосом («давай поговорим о личном» / «хватит о личном») или после 10 минут тишины. Телефон показывает значок «Личное» по этому сообщению, а не по своей кнопке |
| `{"type":"enroll","count":3,"needed":5,"mode":"strict"}` | Голос владельца: сколько фраз записано из нужных, режим сервера (`off` — проверки нет, `log` — сверяет и отвечает всем, `strict` — отвечает только владельцу). Сразу после `hello` и после каждой фразы записи; `"error":"…"` — почему фраза не принята (например, слишком короткая) |

Ответ без голоса тоже допустим: `reply`, а за ним сразу `audio_end`, без `audio`.
Сервер должен ответить в течение 30 с после `stop`, иначе телефон сочтёт, что ответа не будет.

## Один оборот

```
телефон                                   сервер
  «Орфей» услышано, пик
  start ─────────────────────────────────▶
  PCM, PCM, PCM … ───────────────────────▶ (распознаёт по ходу)
                   ◀───────────────────── end_of_speech   (необязательно)
  stop, пик «принял» ────────────────────▶
                   ◀───────────────────── transcript
                   ◀───────────────────── reply …
                   ◀───────────────────── audio {sample_rate}
                   ◀───────────────────── PCM, PCM …
                   ◀───────────────────── audio_end {expect_reply}
  доиграл ответ → слушает продолжение 6 с (если включено) → снова ждёт «Орфей»
```

## Раздел «Личное»

Отдельная память для личных разговоров: факты, заметки и разговоры хранятся в своём файле базы
на сервере, `personal.db.enc`, **зашифрованном** (AES-256-GCM, `orpheus/secure.py`). Ключ на диске сервера
не лежит: он хранится в приложении (обёрнут ключом Android Keystore) и приходит в `hello`; сервер держит
его только в памяти. Пока ключа нет, «Личное» закрыто: команда голосом получает ответ «Личное закрыто…»,
сообщение `mode` — `error` и `mode:false`. Неверный ключ — `error` «Ключ «Личного» не подходит», файл не
трогается. Новый ключ: `python -c "from orpheus.secure import new_key; print(new_key())"` — сохраните
его копию в надёжном месте: без ключа личную память не открыть.

Вход и выход — голосом или сообщением `mode`; сервер переключает раздел сам и сообщает о каждой смене.
Текст личных фраз и ответов не пишется в журнал сервера — только время.

## Голос владельца

Сервер сверяет голос каждой фразы с голосом владельца (`orpheus/voiceprint.py`, модель CAM++).
Голос записывается один раз из приложения: «Настройки → Мой голос», пять фраз вслух, каждая
отправляется как обычная фраза с `"enroll": true`. Пока голос не записан или сервер в режиме
`off`, отвечают всем, как раньше. Режим и порог задаются на сервере
(`ORPHEUS_SPEAKER`, `ORPHEUS_SPEAKER_THRESHOLD`); текст чужой фразы не пишется ни в журнал, ни в память.
