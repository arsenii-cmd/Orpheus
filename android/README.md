# Орфей для Android

Телефон как умная колонка: в фоне ждёт слово «Орфей», по нему пикает и передаёт
фразу серверу Орфея, проигрывает ответ его голосом и несколько секунд ждёт
продолжения. На самом телефоне распознаётся только слово «Орфей» (Vosk, офлайн).
Всё остальное делает сервер, протокол описан в [../docs/android-protocol.md](../docs/android-protocol.md).

## Как ведёт себя

| Сфера | Что происходит |
| --- | --- |
| тусклый уголёк | Выключен |
| синяя, дышит внутри мерцающего кольца | Ждёт «Орфей» |
| голубая, из неё растут лучи-спектр в такт голосу | Слушает фразу (после сигнала «начал слушать»: два восходящих тона) |
| фиолетовая, вокруг летают кометы по наклонным орбитам | Фраза передана (сигнал «принял»: два нисходящих тона), ждёт ответа |
| золотая, вокруг проявляется лира, струны дрожат | Говорит ответ |
| бирюзовая, лучи и кольцо | Слушает продолжение без слова «Орфей», 6 с (настраивается или выключается) |

«Настройки → Мой голос»: прочитать вслух пять фраз, и сервер будет узнавать владельца по голосу.
В строгом режиме сервера чужой голос (телевизор, гости) остаётся без ответа; телефон просто
продолжает ждать «Орфей». Подробности — в разделе «Голос владельца» протокола.

Каждая смена состояния перетекает, а не переключается: форма, свет, цвет неба и
подпись меняются пружинами, из сферы расходится ударная волна, телефон слегка
вибрирует. Ответ проявляется в чате по словам, пока приходит. Кнопка «Включить»
сжимается в кольцо, а из неё вырастает «Говорить». Если в системе выключены
анимации («Удалить анимацию»), движение останавливается, а цвета и состояния остаются.

- Работает при закрытом приложении и выключенном экране: это foreground-служба с
  микрофоном и постоянным уведомлением, в котором есть кнопки «Говорить» и «Выключить».
- Пока Орфей говорит, слово активации не слушается, чтобы он не будил сам себя.
  Перебить его можно кнопкой «Говорить».
- Команду можно сказать сразу, без паузы: «Орфей, какая погода». Всё, что прозвучало
  после слова, берётся из буфера и не теряется.
- Включать нужно из приложения. После перезагрузки телефона Android не даёт службам
  с микрофоном запускаться сами, так что после неё Орфея надо включить заново.

## Сборка

Нужны Android SDK (platform 36) и JDK 17. Из этой папки:

```sh
scripts/fetch_wake_model.sh     # один раз: модель Vosk (~45 МБ) в assets
./gradlew assembleRelease       # app/build/outputs/apk/release/app-release.apk (~60 МБ)
adb install -r app/build/outputs/apk/release/app-release.apk
./gradlew testDebugUnitTest     # тесты логики
```

Сборка только под `arm64-v8a`, это все телефоны последних лет. Релиз подписан
отладочным ключом.

## Проверка без настоящего сервера

```sh
pip install websockets numpy sherpa-onnx
python tools/mock_server.py --save /tmp/phrases
```

В приложении: «Настройки» → адрес `ws://<IP этого компьютера>:8765/ws`, токен пустой.
Мок отвечает голосом Piper, сколько секунд длилась фраза. С `--save` он сохраняет
каждую принятую фразу в WAV, чтобы услышать, что именно прислал телефон.

## Первый запуск на телефоне

1. «Включить Орфея» и разрешить микрофон и уведомления.
2. «Разрешить работу в фоне без ограничений»: без этого часть телефонов (Xiaomi,
   Samsung, Huawei) через какое-то время убивает службу. На Xiaomi ещё нужно в
   настройках приложения поставить «Автозапуск» и «Без ограничений» в контроле активности.
3. При первом включении модель слова активации распаковывается несколько секунд.
4. Если Орфей срабатывает на посторонние слова, подними «Строгость» в настройках.
   Если не отзывается, опусти.

## Устройство

| Файл | Что делает |
| --- | --- |
| `AssistantMachine.kt` | Состояния и переходы (ждёт → слушает → думает → говорит → продолжение), таймауты. Чистый Kotlin, покрыт тестами |
| `OrpheusService.kt` | Служба: микрофон, слово активации, передача звука, уведомление |
| `WakeWord.kt` | Грамматика Vosk: «орфей» и похожие слова-ловушки, выбор слова по уверенности |
| `Audio.kt` | VAD по громкости, кольцевой буфер на 10 с, PCM |
| `ServerLink.kt` / `Protocol.kt` | WebSocket с переподключением, сообщения протокола |
| `Sound.kt` | Проигрывание ответа, звуковые сигналы (синтезируются, без файлов) |
| `ui/Orb.kt` | Сфера: жидкое тело, лучи, кометы, лира, ударная волна. Один кадровый таймер, рисование без перекомпоновки |
| `ui/Backdrop.kt` | Небо: полярное сияние в цвет состояния, звёзды на трёх глубинах |
| `ui/Screens.kt` | Главный экран, чат с проявлением по словам, кнопки, настройки, переход между экранами |
| `ui/Motion.kt` | Общие пружины, кинетический текст, блик по тексту, нажатие с пружиной, ступенчатые появления |
| `ui/Theme.kt` | Цвета состояний, шрифты (Unbounded и Manrope, OFL, `res/font`, лицензии в `licenses/`) |

### Посмотреть интерфейс без телефона

`tools/ui-preview` собирает тот же код `ui/` на Compose Desktop и проигрывает
сценарий (выключен → включён → слушает → думает → отвечает → настройки) кадр за кадром.
Нужны только JDK и интернет до Maven Central, Android SDK не нужен:

```sh
cd tools/ui-preview
gradle render -Pout=/tmp/frames            # 720 кадров PNG, 400 × 860 dp
ffmpeg -framerate 30 -i /tmp/frames/f%05d.png -pix_fmt yuv420p orpheus-ui.mp4
```

Код `ui/` поэтому пишется только на общем Compose (foundation, animation, material3),
без Android API: всё платформенное (шрифты из `R`, настройка анимаций) передаётся
из `MainActivity`. Типы приложения, которые нужны экрану, в стенде заменены
заглушками (`tools/ui-preview/src/main/kotlin/dev/arco/orpheus/Stubs.kt`): при изменении
`Settings`, `Phase` или `Line` их нужно поправить и там.
